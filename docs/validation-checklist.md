# Локальний чекліст перевірки UML-набору

## Варіанти використання

- [X] Є актори `ClubMember`, `Instructor` і `Administrator`.
- [X] Показані купівля абонемента, бронювання, формування розкладу, контроль заповненості та заморожування.
- [X] Кожен актор пов'язаний принаймні з одним варіантом використання.

## Діаграми класів і послідовності

- [X] Є абстрактний `ClubParticipant`, три похідні ролі й інтерфейс `IClassSchedule`.
- [X] Показані наслідування, реалізація, залежність і агрегація або композиція.
- [X] Кожен клас має атрибут або метод; ролі мають конструктори.
- [X] Усі об'єкти послідовнісної діаграми мають назви класів із `class.mmd`.

## Діаграма станів

- [X] Є початковий і кінцевий стани.
- [X] Є купівля, бронювання, заморожування та поновлення абонемента.

## CRC-книга

- [X] Є окрема картка для кожного класу предметної області без пропусків і дублікатів.
- [X] Заголовки карток мають формат `Клас: {ClassName}`.
- [X] Колонки мають точні назви `обов'язки класу` та `з ким співпрацює`.

## Бізнес-сценарії

- [X] Активний абонемент дозволяє бронювання за наявності місць.
- [X] Бронювання відхиляється, якщо місць немає.
- [X] Інструктор створює валідне заняття; неповні дані або час поза графіком відхиляються.
- [X] Адміністратор бачить зайняті й вільні місця, зокрема для заповненого залу.
- [X] Некоректне чи повторне заморожування не змінює абонемент.

## Повний комплект

- [X] Існують усі п'ять очікуваних файлів у `docs/`.
- [X] Усі назви класів і методів англійські, пояснення — українські.
